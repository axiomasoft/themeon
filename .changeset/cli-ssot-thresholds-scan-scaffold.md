Fix `themeon check` running every contrast pair at the `usage: 'body'` threshold (|Lc| 75) while
the package's own `@themeon/css` generation gate used `'text'` (60) for the same pairs — the
package's own default theme failed its own linter (audit #22, Major). `checks/contrast.ts` now
reads pairs and thresholds from the single SSOT (`SEMANTIC_CONTRAST_PAIRS`/`checkThemeContrast`,
`@themeon/colors`); the local 3-pair table is gone.

Fix the source scanner not excluding ThemeOn's own generated output (audit #23, Major):
`--out`/`--tailwind`/`config` paths are now excluded by default, plus a content-based skip for any
file carrying a `generated by @themeon/...` banner — previously `unused`-detection silently
counted the generated bridge file's own tokens as "used", and `hardcode`-detection flagged the
generated tokens file itself. A new `--ignore <glob>` flag lets a consumer add more exclusions. A
scan that ends up covering zero sources after exclusions now emits `warning: no sources scanned`
instead of reporting a silent, meaningless "clean".

`themeon init` now scaffolds the theme config at `theme/theme.config.ts` (not the project root) —
a root-level theme file defeats `@themeon/nuxt`'s directory-scoped dev-watcher and forces a full
restart on every edit instead of granular CSS HMR. `init`/`build`/`check` share one default path
via the new `DEFAULT_THEME_CONFIG_PATH` constant, so running them without an explicit `--config`
no longer resolves to three different files.

New `--out` flag on `themeon build` (default `tokens.css`) makes the previously-implicit output
path explicit and consistent with the new scan-exclusion logic above.
