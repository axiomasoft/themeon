### P0.6 — Measured critical coverage gates

**Intent:** Introduce staged, risk-oriented coverage gates for critical modules using a measured
baseline and explicit ratchet, integrated into the reusable verification path.

**Why:** `RAG:—` `vitest.config.ts` selects V8 coverage but has no thresholds and root CI never
runs coverage. An arbitrary monorepo global percentage would punish new packages without proving
resolver, naming, DTCG or tenant safety.

**Scope Included:** Capture per-file/package baseline for resolver/graph-equivalent paths, naming,
DTCG conversion, tenant patching, serialization, framework glue and CLI presentation; define
critical include/exclude sets; set initial non-regressive thresholds and documented target ratchet;
add deterministic coverage command/report; wire the gate to reusable verification; tests for config
selection where practical.

**Scope Excluded:** Claiming 100% as a quality metric; lowering current measured critical coverage;
mutation testing (P2); browser E2E coverage; generated/dist/docs/fixture coverage; unrelated test
refactors solely to increase line count.

**Inputs:** `audits/2026-09-19-audit.md`; `vitest.config.ts`; `package.json`;
`.github/workflows/ci.yml`; `packages/core/src/resolve.ts`; `packages/core/src/naming.ts`;
`packages/core/src/patch.ts`; `packages/core/src/dtcg/from-dtcg.ts`

**Files:** `vitest.config.ts`; `package.json`; `.github/workflows/ci.yml`;
`.github/workflows/verify.yml`; `docs/architecture/testing-strategy.md`;
`coverage-baseline.json`; affected focused test files under `packages/core/src/**`,
`packages/colors/src/**`, `packages/cli/src/**`

**Required Reads:** 1) `plan.md`; 2) `phases/P0/P0.md`; 3) `audits/2026-09-19-audit.md` (section “Coverage gates”);
4) `vitest.config.ts`; 5) `package.json`; 6) `.github/workflows/ci.yml`;
7) `tests/integration/vitest.config.ts`; 8) `packages/core/src/resolve.test.ts`;

13) `packages/cli/src/check.test.ts`

**Implementation Rules:** Measure before selecting thresholds. Store tool version, include set and
per-file values; no generated timestamps that make the baseline nondeterministic. The first gate is
non-regressive and cannot be lower than measured baseline without a named deviation. Targets from
the audit are goals, not fabricated current coverage. Critical new files start gated immediately;
noncritical packages use a lower package-level policy or no threshold with rationale.

**Code Guidance:** Prefer Vitest's native per-file thresholds/configuration and a small deterministic
baseline comparator over a bespoke coverage engine. Keep one root command suitable for CI. Add
tests only for uncovered behavior, not empty assertions or ignore comments; new ignores require a
reason adjacent to the configuration.

**Validation:** Run focused coverage command twice and compare the normalized baseline/report;
prove the gate fails when a critical threshold is raised above observed coverage in a temporary
config/test harness, then restore it; `pnpm test`, `pnpm typecheck`, `pnpm lint`; reusable verify
workflow includes the same coverage command exactly once.

**Deliverables:** Measured deterministic baseline; risk-ranked threshold config and ratchet policy;
CI coverage command/gate; targeted tests only where real behavior was previously uncovered;
documentation of included/excluded paths and remaining gaps.
