### P0.3 — Tenant patch security envelope

**Intent:** Define and enforce bounded policies for untrusted tenant patches across parser,
runtime validator and schema, with adversarial tests proving fail-closed behavior.

**Why:** Tenant patching is a high-value external-input seam. `RAG:—` unsafe prototype segments
are already rejected in `define.ts`, but the audit names unresolved depth/size, CSS resource,
Unicode, cross-tenant and schema/runtime-divergence risks. Later IR work must inherit a secure
baseline rather than redesigning it opportunistically.

**Scope Included:** Threat model and trust levels `branding | extended | trusted`; limits for depth,
key count and value length; reserved keys and Unicode controls; policy for `url()`, `@import`, CSS
breakout/unclosed constructs and invalid surrogates; post-patch alias-cycle/reference validation;
prevention of patching internal/primitive paths where policy forbids it; schema/runtime parity and
adversarial fixtures; cross-tenant isolation invariant.

**Scope Excluded:** General-purpose CSS sanitizer; fetching/validating external resources; tenant
storage/authentication; applying one tenant's output as another tenant's base; canonical IR changes;
trusted owner-authored arbitrary stylesheet support.

**Implementation Rules:** Treat tenant JSON as hostile and reject over-limit input before deep
recursion or expensive graph work. One policy definition drives runtime and JSON Schema outputs;
tests fail on divergence. Default policy is the narrowest safe public option, with `trusted`
requiring explicit selection. Rejection carries stable code/path/hint and never includes a secret
or full hostile payload. Preserve existing safe inputs and current prototype-key protection.

**Code Guidance:** Centralize bounds/policy as immutable data consumed by grammar/schema/runtime;
do not maintain three allowlists. Test raw JSON objects including own `__proto__`, `constructor`
and `prototype` keys. Use generated boundary fixtures at limit−1/limit/limit+1 and assert bounded
failure time/stack behavior. Validate patched graphs before serialization/application.

**Validation:** Focused core tests for patch/grammar/schema/define/resolve; `pnpm --filter
@themeon/core test`; `pnpm --filter @themeon/core typecheck`; `pnpm --filter @themeon/core build`;
schema/runtime parity test; adversarial suite covers every audit bullet or documents an explicit
out-of-scope threat with rationale; no cross-tenant state is retained between calls.

**Deliverables:** Security model; policy-level public contract; bounded validator/grammar/schema;
stable security diagnostics; adversarial fixtures and parity proof.
