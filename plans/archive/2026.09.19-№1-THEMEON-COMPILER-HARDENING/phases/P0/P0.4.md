### P0.4 — Trusted release and reusable verification

**Intent:** Make release reuse the complete verification pipeline and replace long-lived npm-token
publishing with owner-configured trusted publishing/provenance, without publishing a release.

**Authority:** routine

**Why:** `RAG:—` `.github/workflows/release.yml` builds and publishes with `secrets.NPM_TOKEN`
without rerunning lint/typecheck/unit/integration/package gates. Changing repository workflows is
reversible, but external npm/GitHub trust settings require owner authority and exact package scope.

**Scope Included:** Reusable verify workflow or equivalent single source used by CI and release;
minimal permissions; OIDC `id-token: write` only in publish job; immutable SHA pins for third-party
actions; provenance-ready publish job shape; tarball artifacts and dry-run manifest diff;
dependency review/CodeQL/Scorecard/SBOM gates where supported; documented migration, rollback and
token-fallback residual. In-plan close is repository+CI plumbing (D10).

**Scope Excluded:** Actual version bump, changeset consumption, tag, npm publish, release notes;
rotating/deleting secrets before trusted publishing is proven; widening GitHub organization policy;
adding paid security services; changing package contents beyond verification plumbing; **completing**
the owner-gated npm trusted-publisher grant or GitHub protected `release` environment — residual
outside this plan (D10). The gate remains documented; it is not in-plan GREEN.

**Inputs:** `audits/2026-09-19-audit.md`; `.github/workflows/ci.yml`;
`.github/workflows/release.yml`; `package.json`; `.changeset/config.json`

**Files:** `.github/workflows/ci.yml`; `.github/workflows/release.yml`;
`.github/workflows/verify.yml`; `.github/workflows/dependency-review.yml`;
`.github/dependabot.yml`; `package.json`; `docs/architecture/release-security.md`;

9) `packages/cli/package.json`; 10) `packages/css/package.json`; 11) `pnpm-workspace.yaml`

**Implementation Rules:** Repository-only preparation is the in-plan work (D10). External npm/GitHub
trust settings and removal of the token fallback wait for the exact grant and are not required to
re-admit this item. Release consumes the same verify definition/commit, not a loosely parallel
checklist. Third-party actions pin full immutable SHA with version comment. Permissions default
empty/read and elevate per job. Secrets are never printed or copied into artifacts. No workflow
path can publish from pull_request or unprotected ref.

**Code Guidance:** Separate pure verification from publish authority. Preserve Changesets unless a
proved incompatibility requires a decision. Use a dry-run pack/manifest job before publish and make
publish depend on all named checks. Keep slow browser/release-only lanes explicit instead of hiding
them behind a generic green CI job.

**Validation:** Parse workflows; actionlint or repository-equivalent static validation; run the
reusable verification locally where commands are host-safe; `pnpm build`, `pnpm lint`, `pnpm
typecheck`, `pnpm test`, `pnpm test:int`, `pnpm check:pack`; dry-run pack artifact diff; prove by
workflow inspection that publish has OIDC and no PR path. External trusted-publisher setup is
**not** required for in-plan close; record `artifacts/P0.4/external-trust.json` with
`predicate_satisfied: false` as the residual (D10). Re-admission result is `closed-deviations`.

**Deliverables:** Single reusable verification path; hardened CI/release workflows; pinned actions
and minimal permissions; trusted-publishing setup/rollback guide naming the residual owner gate;
dry-run/tarball/SBOM evidence; no release side effect; D10 deviation recorded. Owner-approved
external configuration receipt is **out of plan**.
