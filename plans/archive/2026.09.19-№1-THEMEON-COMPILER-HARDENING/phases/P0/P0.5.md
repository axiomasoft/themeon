### P0.5 — Publication/package truth and dependency hygiene

**Intent:** Reconcile public documentation and manifests with observed package registry state, and
remove redundant workspace devDependency declarations without changing runtime dependency edges.

**Why:** `RAG:—` README says “unpublished” while current commit message says npmjs publication;
`packages/cli/package.json` and `packages/naive/package.json` duplicate workspace packages in both
dependencies and devDependencies. Consumers need one accurate status and auditable manifest intent.

**Scope Included:** Verify actual npm registry visibility/version for every public package; update
README/docs changelog/installation status; explain `0.0.0` repository versions and Changesets flow;
remove only redundant workspace devDependency entries already present as runtime dependencies;
verify package exports/files/sideEffects descriptions remain accurate; add a lightweight manifest
consistency check if needed.

**Scope Excluded:** Publishing, version bump, changeset creation, dependency upgrades, moving a
dependency between runtime/peer solely for style, changing CSS export names, broad documentation
rewrite.

**Implementation Rules:** Registry state, not commit wording, decides publication prose. Do not
remove peer-only development fixtures needed for tests. A workspace package already in
`dependencies` remains available during development; remove only byte-identical duplicate entries.
Keep lockfile changes empty unless the package manager proves a lockfile normalization is required.
Manifest check reports exact package/path and does not infer publication from `version: 0.0.0`.

**Code Guidance:** Build a small table of package → registry observed version → local placeholder →
docs claim before editing. Prefer a deterministic Node stdlib script if automation is justified;
do not add a dependency for manifest comparison. Test CSS sideEffects and exports through existing
pack checks instead of duplicating their implementation.

**Validation:** `pnpm install --frozen-lockfile`; `pnpm build`; `pnpm typecheck`; `pnpm test`;
`pnpm check:pack`; manifest consistency script if added; registry evidence covers each package;
`git diff -- pnpm-lock.yaml` is empty unless explicitly justified.

**Deliverables:** Accurate publication/install/release prose; documented placeholder-version
mechanism; deduplicated CLI/Naive workspace dependencies; optional deterministic manifest check;
GREEN package verification.
