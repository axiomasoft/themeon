### P3.4 — Evidence-based testing-kit disposition

**Intent:** Convert the P2 reuse evidence into either a deliberately internal fixture toolkit or an independently supported `@themeon/testing` contract.

**Why:** Publishing helpers too early creates permanent public surface; leaving duplicated proven helpers internal wastes leverage.

**Scope Included:** Reuse/invariant inventory; vendor-vs-build check; decision; deduplication; package manifest/exports/docs only if publication criteria pass.

**Scope Excluded:** npm publish; product semantics; package creation without P2 evidence.

**Inputs:** `phases/P2/P2.1.state.md`; `phases/P2/P2.3.state.md`; `phases/P2/P2.6.md`; `phases/P2/P2.6.state.md`; `decisions/D4-consumer-gated-ecosystem.md`; `package.json`

**Files:** Internal test helpers or `packages/testing/**`; affected tests; decision/docs; workspace/package config only on package branch.

**Required Reads:** `plan.md`; `phases/P3/P3.md`; `phases/P2/P2.1.md`; `phases/P2/P2.3.md`; `phases/P2/P2.6.md`; `decisions/D4-consumer-gated-ecosystem.md`; `package.json`; `pnpm-workspace.yaml`; `packages/core/package.json`

**Implementation Rules:** Package branch requires two independent reuse sites, small stable API and no private-core imports; otherwise document internal ownership.

**Code Guidance:** Extract only stable primitives; avoid framework mega-fixtures; keep package branch tree-shakeable and runtime-light.

**Validation:** Decision criteria trace; all former consumers green; package branch additionally builds/types/packs from tarball; no duplicated helper remains in selected scope.

**Deliverables:** Accepted disposition, consolidated toolkit, and package contract only if evidence passes.
