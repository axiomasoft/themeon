### P3.5 — Evidence-gated stylelint integration

**Intent:** Add editor-time CSS-token diagnostics only when stable manifest/IR evidence and real consumer need justify the integration.

**Why:** A linter tied to unstable internals would drift; stable emitted artifacts can support focused rules without compiler duplication.

**Scope Included:** Need/reuse decision; minimal rules for unknown token/custom-property and deprecated token; manifest-based resolver; false-positive/negative fixtures.

**Scope Excluded:** CSS parser invention; arbitrary style policy; package publication without decision; runtime compiler access.

**Inputs:** `phases/P3/P3.3.md`; `phases/P3/P3.3.state.md`; `phases/P2/P2.6.state.md`; `decisions/D4-consumer-gated-ecosystem.md`

**Files:** Internal tool or `packages/stylelint-plugin/**`; fixtures/docs/config; decision file.

**Required Reads:** `plan.md`; `phases/P3/P3.md`; `phases/P3/P3.3.md`; `phases/P3/P3.3.state.md`; `phases/P2/P2.6.md`; `packages/css/package.json`; `packages/vite/package.json`; `decisions/D4-consumer-gated-ecosystem.md`; `ROADMAP.md`

**Implementation Rules:** If evidence threshold fails, close as `Skipped by decision` with rationale; plugin branch reads versioned artifact and degrades explicitly on schema mismatch.

**Code Guidance:** Use Stylelint public APIs; rule messages/codes stable; avoid filesystem discovery magic; offer explicit manifest path.

**Validation:** Decision trace; plugin branch rule-tester fixtures, schema mismatch and packed install/build; internal/skip branch verifies no dangling docs/config.

**Deliverables:** Evidence-backed skip or selected lint integration with tests and docs.
