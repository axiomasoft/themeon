### P3.1 — Versioned inspect, explain and graph CLI

**Intent:** Expose compiler state, provenance and reference graph through human and versioned machine-readable CLI surfaces.

**Why:** Users need to understand compiled values and failures without duplicating resolver logic in the CLI.

**Scope Included:** `inspect`, `explain`, `graph`; pretty/json/github diagnostic formatters; output schema/version; exit-code contract.

**Scope Excluded:** Semantic diff/migration; IDE plugin; alternate resolver.

**Inputs:** `phases/P1/P1.3.state.md`; `phases/P1/P1.4.state.md`; `phases/P1/P1.5.state.md`; `phases/P2/P2.1.state.md`; `phases/P2/P2.4.state.md`; `phases/P2/P2.6.state.md`

**Files:** `packages/cli/src/**`; CLI schemas/golden tests; core public types only when already approved by P1.

**Required Reads:** `plan.md`; `phases/P3/P3.md`; `phases/P1/P1.closed.md`; `phases/P2/P2.4.md`; `packages/cli/src/cli.ts`; `packages/cli/src/index.ts`; `packages/core/package.json`

**Implementation Rules:** CLI is a consumer of public compiler contracts; JSON fields are versioned and deterministic; stdout/stderr and exit codes are explicit.

**Code Guidance:** Share one query layer across formatters; render provenance/cycles without exposing private paths; cap graph output with diagnostics.

**Validation:** Golden and schema tests; repeated output byte-identical; error/exit matrix; packed CLI smoke; affected/root checks green.

**Deliverables:** Three commands, versioned schemas, formatters, exit contract and usage docs.
