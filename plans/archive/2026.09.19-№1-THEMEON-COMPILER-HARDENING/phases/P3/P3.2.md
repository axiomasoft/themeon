### P3.2 — Semantic diff, doctor and migration dry-run

**Intent:** Classify theme/API changes and offer evidence-backed, non-mutating diagnostics and migration hints.

**Why:** Text diffs cannot distinguish value, reference, metadata and breaking public-surface changes safely.

**Scope Included:** `diff`; `doctor`; dry-run migration hints; versioned change classes; before/after provenance; machine and human formats.

**Scope Excluded:** Automatic write migration; source rewriting without owner command; semver release automation.

**Inputs:** `phases/P3/P3.1.md`; `phases/P3/P3.1.state.md`; `phases/P1/P1.1.state.md`; `phases/P1/P1.5.state.md`; `phases/P2/P2.4.state.md`

**Files:** `packages/cli/src/**`; diff/migration schemas; fixtures/golden tests; docs.

**Required Reads:** `plan.md`; `phases/P3/P3.md`; `phases/P3/P3.1.md`; `phases/P3/P3.1.state.md`; `phases/P1/P1.closed.md`; `phases/P2/P2.4.md`; `decisions/D2-dtcg-loss-policy.md`; `packages/cli/src/cli.ts`

**Implementation Rules:** Dry-run by default; every hint names confidence/evidence; unknown change is not classified safe; machine contract is additive/versioned.

**Code Guidance:** Compare canonical representations, not serialized order; separate classification from rendering; test rename-like ambiguity explicitly.

**Validation:** Breaking/non-breaking/unknown fixture matrix; no-write assertion; deterministic output; packed CLI and root verification.

**Deliverables:** Diff/doctor commands, dry-run hints, versioned classifications and safety fixtures.
