### P2.5 — Portable performance and HMR budgets

**Intent:** Establish reproducible compiler/build/HMR/runtime baselines and regression policies tied to measured environment noise.

**Why:** Performance promises without controlled inputs and variance create flaky gates or hide scale regressions.

**Scope Included:** Small/medium/large theme corpus; cold/warm compiler and fingerprint timing; Vite rebuild/HMR and runtime apply metrics; memory where stable; budget policy.

**Scope Excluded:** Network service benchmarks; universal hardware numbers; premature micro-optimization.

**Inputs:** `phases/P1/P1.closed.md`; `phases/P1/P1.5.state.md`; `phases/P2/P2.3.state.md`; `packages/vite/src/index.ts`; `packages/core/src/apply.ts`

**Files:** `benchmarks/**`; benchmark scripts/config; periodic CI workflow; `docs/testing/performance.md`.

**Required Reads:** `plan.md`; `phases/P2/P2.md`; `phases/P1/P1.closed.md`; `phases/P2/P2.3.md`; `packages/vite/src/index.ts`; `packages/vite/src/index.test.ts`; `packages/core/src/apply.ts`; `.github/workflows/ci.yml`; `audits/2026-09-19-audit.md`

**Implementation Rules:** Record hardware/runtime/tool versions; noisy measurements are informational; gating uses statistically defensible repeated samples and coarse budgets.

**Code Guidance:** Separate setup from timed region; assert output correctness; retain machine-readable baselines; include a known-regression self-test.

**Validation:** Repeatability report; budget gate detects injected delay; outputs/fingerprints match correctness fixtures; periodic lane completes within cap.

**Deliverables:** Corpus, benchmark harness, baselines, regression policy and CI lane.
