# P2 — Verification and external-consumer contracts

## Phase Context

P2 proves the new P1 contracts under generated inputs, packaged consumption, declaration changes,
browser/runtime conditions and scale. It selects each tool only after checking ecosystem fit and
locks checks to behavior/risk rather than a fixed test-fashion checklist.

> **Контракт фазы (contract-first).** Потребляет: terminal P1 compiler contracts, P0 coverage and
> security policies. Производит: property and mutation evidence, packed-consumer matrix, API/type
> reports, performance budgets, browser/runtime/adapter conformance and reusable fixtures. Границы:
> verification does not introduce new product semantics; defects return to their owning contract.

> **Phase Assurance | v1.**
> Impact: internal-integration
> Integration Seams: packed-consumers · roundtrip-properties · browser-runtime · ci-lanes
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: Every verification item has a bounded behavior target and deliberate lane; review
> depth follows public/package/security impact instead of requiring an independent audit by default.

## DoR (Definition of Ready)

- [x] P1 item contracts name the public/IR/compiler receipts consumed by P2.
- [x] Tool reuse/vendor checks are required before adoption in P2.1/P2.2/P2.4.
- [x] Slow/nightly/release lane budgets are deliverables of their owning items.
- [x] Performance baselines must name environment or remain non-gating.
- [x] Verification cannot change product semantics without returning to the owning phase.

## Scope Included

Property-based tests for resolver/graph/naming/DTCG/patch/serialization; mutation testing of named
critical logic; DTCG round-trip and official/external fixtures; packed-tarball consumers for TS ESM,
Vite, Vue, Nuxt SSR, Laravel Vite, Tailwind, DOM-free Node and module-resolution variants; API
declaration reports/type compatibility fixtures; benchmarks and regression budgets; periodic
Firefox/WebKit runtime checks; adapter consumed/ignored/diagnostic conformance; shared testing
fixtures with a publication decision only after reuse is observed.

## Scope Excluded

Arbitrary coverage maximization; benchmarking network services; full browser matrix on every PR;
new framework adapter; product feature changes hidden as test fixes; publishing `@themeon/testing`
without a proved independent consumer.

## Dependencies

P1 terminal. Property/round-trip tests follow stable IR; consumer/API tests follow subpath/package
exports; performance baseline follows compiler stabilization; testing-package publication verdict
follows at least two actual reuse sites.

## Files (ожидаемая область записи)

`packages/*/src/**/*.test.ts`; `packages/*/test/**`; `tests/integration/**`; `tests/consumers/**`;

## Validation (ожидаемая форма)

Focused suites plus full root verification; pack/install/typecheck/build/import in clean temporary
consumers; mutation report with named critical scope; API report diff visible and gated; benchmark
runner deterministic enough for its lane and proves its own regression failure; Chromium PR lane
plus Firefox/WebKit periodic lane; no workspace-resolution shortcut in packed-consumer evidence.

## Phase Handoff

On GREEN close, execute the already-designed P3 against proven diagnostic/manifest/fixture
contracts. Evidence may select an allowed branch in P3.4/P3.5; it may not silently expand scope.
