  hardcode), выведенные напрямую из найденных багов (§4.10 master). Каркас — citty 0.2.2 (unjs,
  ESM-only подтверждён), логгер consola, glob tinyglobby.

### P4.1 — `@themeon/tailwind`: скелет пакета + `tailwindBridge()` генератор `@theme inline`

**Status:** 🟠 Done with deviations
**Intent:** Создать пакет `@themeon/tailwind` и реализовать `tailwindBridge(resolved, opts?)` —
чистую функцию `ResolvedTheme → string`, эмитящую CSS-блок `@theme inline { … }`, где каждый
sys-токен, попадающий в Tailwind-namespace (D5: `--color-*`, `--spacing-*`, `--radius-*` …),
получает **self-referential** mapping `--x: var(--x);`. Этот файл потребитель `@import`'ит рядом
с `@import "tailwindcss"`; Tailwind генерирует из него утилиты (`bg-action-primary`, `p-md` …),
чьи значения — inline-`var(--x)` → runtime-своп темы (`[data-theme]`) доходит до утилит без
ребилда.
**Why:** L3-мост в Tailwind v4, несущая причина всей архитектуры (§4.4 master). `@theme inline`
**обязателен, не опция** (P-D31, R-14 §2.1): non-inline `@theme` создаёт глобальную `:root`-
переменную, чья подстановка резолвится в скоупе `:root` и НЕ переопределяется под
`[data-theme=dark]` → тёмная тема ломается; inline встраивает `var(--ref)` прямо в утилиту → ре-
резолв в каждом подскоупе → своп работает. Tailwind v4 генерирует утилиты ТОЛЬКО из `@theme`-
переменных, не из произвольных `:root` → бридж обязателен (R-14 §2.3). Первый item фазы — самый
механический, без зависимостей от других P4-пакетов.

**Implementation Rules:**
1. `dependencies`: ровно `{ "@themeon/core": "workspace:*" }`. `devDependencies`: `@themeon/core:
   workspace:*`, `tailwindcss: catalog:`, `@tailwindcss/vite: catalog:`, `tsdown`/`typescript`/
   `vitest: catalog:`. Нет `peerDependencies` (bridge — build-time генератор строки, не рантайм-
   плагин; Tailwind нужен только для compile-смока). `sideEffects:false`.
2. `TAILWIND_NAMESPACES` — заморожённый `readonly string[]` из пересечения `NAMESPACE_TABLE`-
   значений и Tailwind-набора: `['color','font','text','font-weight','tracking','leading',
   'breakpoint','spacing','radius','shadow','ease']`. Каждый элемент — namespace ПОСЛЕ `--`
   (первый сегмент var-имени до первого `-`… но namespace может содержать дефис, напр.
   `font-weight` → см. Rule 3 про матчинг).
3. Матчинг namespace: var-имя `--color-action-primary` принадлежит namespace `color`, если
   начинается с `--color-`. Для составных (`--font-weight-bold` vs `--font-sans`): матчить
   по **самому длинному** префиксу из `TAILWIND_NAMESPACES` — сначала пробовать `font-weight`,
   потом `font` (сортировать namespace'ы по убыванию длины при матчинге, иначе `--font-weight-*`
   ложно уйдёт в `font`). Хелпер `matchNamespace(varName): string | null`.
4. Источник имён: по умолчанию (`include:'all'`) — объединение имён из `resolved.tokens` И всех
   `resolved.themes[*]` (тема может вводить var, которого нет в базе). `include:'base'` — только
   `resolved.tokens`. Дедуп по var-имени (Set), стабильная сортировка (лексикографическая) —
   детерминизм вывода (инвариант «пустой diff» пилота P5).
5. **Форма mapping — self-referential (P-D31):** `<varName>: var(<varName>);`. НИКОГДА не
   non-inline `@theme` и не эмит значения (`--color-x: #abc`) — только `var()`-ссылка. Значения
   живут в `tokens.css` потребителя, не в bridge.
6. Вывод — ровно один блок `@theme inline {\n  <mappings>\n}\n`. При `banner:true` (дефолт) —
   первая строка `/* Generated by @themeon/tailwind — do not edit. */`. Отступ 2 пробела,
   `\n`-разделители, финальный `\n`. Пустой набор → `@theme inline {\n}\n` (валидный no-op).
7. Никаких обращений к DOM/FS/сети — чистая функция. Никаких hex/px-литералов (кроме фикстур).
**Code Guidance:**
- Стиль: как ядро — чистые функции, узкие типы, JSDoc (англ.) на `tailwindBridge`/опциях,

- Сигнатуры (реализовать точно):
```ts
// src/namespaces.ts
/** Tailwind v4 namespaces that ThemeOn emits AND Tailwind recognises for utility generation.
 *  ThemeOn extensions (gradient/z/duration) are intentionally excluded — Tailwind ignores them. */
export const TAILWIND_NAMESPACES = [
  'color', 'font-weight', 'font', 'text', 'tracking', 'leading',
  'breakpoint', 'spacing', 'radius', 'shadow', 'ease',
] as const

// src/bridge.ts
import type { ResolvedTheme, CssVarName } from '@themeon/core'
export interface TailwindBridgeOptions {
  /** 'all' = base tokens ∪ all theme patches (union of names); 'base' = only base. Default 'all'. */
  include?: 'all' | 'base'
  /** Restrict emitted namespaces (subset of TAILWIND_NAMESPACES). Default: all of them. */
  namespaces?: readonly string[]
  /** Emit leading "generated" banner comment. Default true. */
  banner?: boolean
}
/** Generate a Tailwind v4 `@theme inline` bridge from a resolved ThemeOn theme.
 *  Every ThemeOn var whose namespace is Tailwind-recognised becomes a self-referential
 *  mapping `--x: var(--x);`, so Tailwind emits utilities that inline `var(--x)` — runtime
 *  `[data-theme]` swaps then reach the utilities without a rebuild (P-D31). */
export function tailwindBridge(resolved: ResolvedTheme, opts?: TailwindBridgeOptions): string
```
- Алгоритм `tailwindBridge`:
  1. `ns = opts.namespaces ?? TAILWIND_NAMESPACES`; отсортировать по убыванию длины (Rule 3).
  2. Собрать имена: `names = new Set<string>()`; из `resolved.tokens` (всегда); при `include!=='base'`
     — из каждого `resolved.themes[k]`. Добавлять `tok.varName`.
  3. Отфильтровать `names` по `matchNamespace(name) !== null` (namespace ∈ `ns`).
  4. Отсортировать оставшиеся лексикографически.
  5. Построить строки `  ${name}: var(${name});`; собрать блок с опц. banner.
- Пример вход→выход (дефолт-тема из `@themeon/css`):
```
tailwindBridge(resolveTheme(defaultTheme))
→
/* Generated by @themeon/tailwind — do not edit. */
@theme inline {
  --color-action-primary: var(--color-action-primary);
  --color-action-primary-hover: var(--color-action-primary-hover);
  --color-bg-page: var(--color-bg-page);
  ...
  --radius-md: var(--radius-md);
  --shadow-md: var(--shadow-md);
  --spacing-md: var(--spacing-md);
  --text-base: var(--text-base);
  ...
}
```
  (Внимание: `--color-on-primary`, `--text-*--line-height` companion double-dash var — companion
  тоже начинается с `--text-` → попадёт в namespace `text`; это допустимо, Tailwind проигнорирует
  неизвестный суффикс, но чтобы не плодить мусор — **исключать companion-переменные с `--`-
  разделителем внутри имени**: если `varName` содержит `--` после первого символа (double-dash
  companion P1.3), пропустить. Задокументировать в Rule/тесте.)
- Compile-смок (`tailwind-compile.test.ts`): в `test/fixtures/` положить `input.css`
  (`@import "tailwindcss"; @import "./bridge.css"; @import "./tokens.css";`), `tokens.css`
  (`serializeThemeCss` дефолт-темы), `content.html` (`<div class="bg-action-primary">`).
  Сгенерировать `bridge.css` через `tailwindBridge`. Скомпилировать Tailwind программно
  (`@tailwindcss/vite` build ИЛИ `tailwindcss` Node API — что доступно в 4.3.2; если Node API
  нестабилен — spawn `npx @tailwindcss/cli -i input.css -o out.css`, но лучше программно).
  Ассертить: `out.css` содержит `.bg-action-primary` с `background-color: var(--color-action-
  primary)`; НЕ содержит второго объявления `--color-action-primary:` вне `tokens.css`-скоупа;

- `mergeOverrides` эталон (~20 LOC):
```ts
const BLOCKED = new Set(['__proto__', 'constructor', 'prototype'])
function isPlain(v: unknown): v is Record<string, unknown> {
  return typeof v === 'object' && v !== null && !Array.isArray(v)
}
export function mergeOverrides(...layers) {
  const out: Record<string, unknown> = {}
  for (const layer of layers) {
    if (!isPlain(layer)) continue
    for (const [k, v] of Object.entries(layer)) {
      if (BLOCKED.has(k) || v === undefined) continue
      out[k] = isPlain(v) && isPlain(out[k]) ? mergeOverrides(out[k], v) : v
    }
  }
  return out as GlobalThemeOverrides
}
```

export async function runBuild(opts) {
  const theme = await loadThemeConfig(resolve(opts.cwd, opts.config))
  const resolved = resolveTheme(theme, { refLayer: opts.refLayer ?? 'referenced', aliases: opts.aliases })
  const outPath = resolve(opts.cwd, opts.out)
  await mkdir(dirname(outPath), { recursive: true })
  await writeFile(outPath, serializeThemeCss(resolved), 'utf8')
  let bridgePath
  if (opts.tailwind) {
    bridgePath = resolve(opts.cwd, opts.tailwind)
    await writeFile(bridgePath, tailwindBridge(resolved), 'utf8')
  }
  consola.success(`themeon build → ${relative(opts.cwd, outPath)}`)
  return { outPath, bridgePath }
}
