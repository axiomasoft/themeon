### P8.2 — `@themeon/vite`: рабочий канал подключения + живой HMR

**Status:** 🟢 Done
**Intent:** Сделать `@themeon/vite` работающим хотя бы одним способом и привести README к тому, что
реально работает: канал — `import 'virtual:themeon.css'` из **JS-энтри**; HMR — `hotUpdate` возвращает
`[mod]` (Vite сам шлёт корректный payload); `tokensFiles` резолвятся в АБСОЛЮТНЫЕ пути от `config.root`.
**Why:** Blocker #1 — все три рецепта README показывают `@import 'virtual:themeon.css'` в CSS, а CSS-
`@import` в Vite резолвится postcss-import'ом по файловой системе: плагинные `resolveId` не участвуют
(RAG:✅ 2026-07-14, воспроизведено на Vite 8.1.4 и 7.3.6: `[postcss] ENOENT … 'virtual:themeon.css'`,
build падает). Major #18 — HMR мёртв. Разведка (`findings/P8-vite-channel-hmr.md` §4) показала, что
дефектов ТРИ, а не два: (а) тип апдейта; (б) `mod.url` виртуального модуля = сырой
`\0virtual:themeon.css`, а НЕ `/@id/__x00__…` (как предполагал аудит) → даже «правильный» ручной
`js-update` был бы no-op; (в) **новый Blocker**: `tokensFiles: ['./theme.config.ts']` из README —
относительный путь, а `hotUpdate({file})` даёт абсолютный → HMR не ожил бы и после фикса (а)+(б).
**Scope Included:**
- `packages/vite/src/index.ts`: резолв `tokensFiles` в абсолютные пути в `configResolved` (от
  `config.root`); `hotUpdate` возвращает `[mod]` (ручной `hot.send` убрать); `invalidateModule` не
  обязателен при `return [mod]` (проверено).
- Опция `alias`-канала для CSS-first (Laravel без JS-энтри): virtual-id → реальный файл через
  `resolve.alias` — документированный синтаксис `@import 'virtual:themeon.css'` остаётся валидным,
  порядок `@import` не ломается (`findings/P8-vite-channel-hmr.md` §6). Это ДОПОЛНИТЕЛЬНАЯ опция, а
  не замена канона.
- `packages/vite/README.md`: все три рецепта переписаны на JS-энтри; Laravel-рецепт — импорт в
  `resources/js/app.js` (в hot-режиме CSS инжектит клиент Vite, в build — Laravel сам эмитит `<link>`
  для CSS-чанков JS-энтри; `resources/css/app.css` трогать не нужно); честно сказано, что тема,
  импортированная статически в `vite.config`, становится config-dependency → Vite делает full reload,
  а не HMR (новый дефект D4 разведки); рабочий живой HMR — через фабрику-загрузчик темы.
- Интеграционные тесты (яруса P8.1): реальный `build()` и `createServer()` + Chromium.
**Scope Excluded:** `enforce:'pre'` + инлайн CSS (отвергнут: на шейпе README молча выбрасывает второй
`@import` при ЗЕЛЁНОМ билде — тихая потеря пользовательского CSS); `injectFouc` для Blade (Laravel не
зовёт `transformIndexHtml` — остаётся ограничением, зафиксировать в README); двойной инстанс
`@themeon/core` (наблюдение разведки — в Pending Work, не в скоуп).
