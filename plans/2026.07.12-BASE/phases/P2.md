5. Каждый CSS-entry начинается с `@import "./layers.css";` — порядок layers объявлен первым statement'ом любого dist-файла (R-12 §5).
6. Тесты колокированы (colors) / в `test/` (css, т.к. тестируется dist); vitest-проект добавляется в общий прогон автоматически (`vitest.config.ts` root: `projects: ['packages/*']`); скрипт `test` пакета — `vitest run --root ../.. --project @themeon/<pkg>` (канон core).

`contrast.ts` — публичный API целиком:

```ts
export type ContrastUsage = 'body' | 'text' | 'large' | 'non-text'

/** Минимальные |Lc| по назначению (APCA Nutshell): body 75, прочий текст 60, крупный/non-text 45. */
export const LC_THRESHOLDS: Readonly<Record<ContrastUsage, number>> = {
  body: 75, text: 60, large: 45, 'non-text': 45,
}

/**
 * Знаковый APCA Lc (fg поверх bg). Отрицательный — light-on-dark; сравнивать по |Lc|.
 * @throws ColorsError('BAD_COLOR') на непарсибельном цвете (fail-closed).
 */
export function contrastAPCA(fg: string, bg: string): number

export interface ContrastPair {
  readonly fg: string
  readonly bg: string
  readonly usage: ContrastUsage
  /** Человекочитаемая метка пары для отчёта: 'text on bg.page'. */
  readonly label?: string
}
export interface ContrastReport {
  readonly pair: ContrastPair
  readonly lc: number
  readonly required: number
  readonly pass: boolean
}
export interface ContrastCheckResult {
  readonly pass: boolean
  readonly reports: readonly ContrastReport[]
}

/** Батч-гейт: pass = ВСЕ пары прошли. Непарсибельная пара = throw (fail-closed), не skip. */
export function checkContrast(pairs: readonly ContrastPair[]): ContrastCheckResult
```

Реализация `contrastAPCA` через colorjs.io. `[VERIFY-ON-IMPL]`: предпочесть tree-shakeable
procedural API `colorjs.io/fn` (https://colorjs.io/docs/procedural) —
`import { contrastAPCA, parse } from "colorjs.io/fn"`; если procedural-вход не экспортирует
contrastAPCA — использовать главный entry (`new Color(fg).contrast(bg, "APCA")`), это
допустимое отклонение (зафиксировать в Known Deviations). Парсинг цвета оборачивать
try/catch → `ColorsError('BAD_COLOR', …с исходной строкой…)`.

Тесты (`contrast.test.ts`):
1. **Референс-векторы**: взять 3–5 канонических пар из официальной документации/тестов APCA
   (https://git.apcacontrast.com/documentation/APCA_in_a_Nutshell.html или тесты
   github.com/color-js/color.js) при исполнении, захардкодить с URL-комментарием, tolerance ±0.5 Lc.
   НЕ выдумывать числа из памяти.
2. Знак: тёмный-на-светлом > 0, светлый-на-тёмном < 0; `#000` на `#fff` даёт |Lc| > 100.
3. Идентичные цвета → |Lc| < 5 (≈0).
4. Fail-closed: `contrastAPCA('не-цвет', '#fff')` бросает `ColorsError` с code `BAD_COLOR`;

5. `checkContrast`: пара body с |Lc| 70 → pass=false, required=75; пара non-text с |Lc| 50 → pass=true.

```ts
export interface ScaleOptions {
  /** Целевая тема шкалы. Деф. 'light'. */
  readonly appearance?: 'light' | 'dark'
  /** Гамма назначения gamut-маппинга. Деф. 'srgb'. */
  readonly gamut?: 'srgb' | 'p3'
}

export interface ScaleStep {
  /** 1..12 (семантика Radix). */
  readonly index: number
  readonly l: number
  readonly c: number
  readonly h: number
  /** 'oklch(0.9931 0.0031 155.2)' — детерминированная сериализация. */
  readonly css: string
  /** '#f8faf8' — всегда sRGB-маппинг (даже при gamut:'p3'), для legacy-потребителей. */
  readonly hex: string
}

/** Ровно 12 элементов. */
export type Scale = readonly ScaleStep[]

/** Роли шагов (Radix-семантика) — для доков/адаптеров. 12 английских строк. */
export const STEP_ROLES: readonly string[]

/** @throws ColorsError('BAD_SEED') на непарсибельном seed. */
export function generateScale(seed: string, opts?: ScaleOptions): Scale
export function generateScalePair(
  seed: string, opts?: Omit<ScaleOptions, 'appearance'>,
): { readonly light: Scale; readonly dark: Scale }
/** Шаги → плоский словарь {'1': 'oklch(…)', …, '12': 'oklch(…)'} для defineTokens. */
export function scaleToTokens(scale: Scale): Record<string, string>
```

Алгоритм словами (реализовать точно в этом порядке):
1. **Парс seed** culori → oklch: `{ l: L₉, c: C₉, h: H }`. `h` undefined (ахромат) → `h = 0`;
   `c` undefined → `c = 0`. Непарсибельно → `ColorsError('BAD_SEED')`.
2. **Lightness**: `L₁ = 0.993` (light) / `0.188` (dark); шаги 1–9 — интерполяция
   `Lᵢ = L₁ + (L₉ − L₁) · tᵢ` по нормированной кривой
   `t = [0, 0.03, 0.085, 0.145, 0.22, 0.31, 0.43, 0.60, 1.0]` (стартовые значения из
   реконструкций Radix — breakcolorui.com/docs/colors, oklch.fyi/color-palettes; правило 7).
   Монотонность 1→9 гарантирована конструкцией при любом seed. Шаг 10 (hover solid):
   `L₁₀ = L₉ − 0.045` (light) / `L₉ + 0.045` (dark), clamp в (0,1).
3. **Chroma** шагов 1–8, 10: `cᵢ = C₉ · min(1.2, g(Lᵢ)/g(L₉))`, где
   `g(L) = exp(−(L−μ)²/(2σ²))`, `μ = 0.60` (light) / `0.66` (dark), `σ = 0.18`.
   Caps поверх формулы: шаг 1 ≤ 0.010, шаг 2 ≤ 0.020 (почти-нейтральные фоны).
4. **Текстовые шаги 11–12 — contrast-solve**: фиксируем chroma
   `c₁₁ = min(C₉ · 0.9, 0.13)`, `c₁₂ = min(C₉ · 0.5, 0.08)`; lightness — бинарный поиск
   (24 итерации) по `L ∈ (0, L₁₀)` (light; для dark — `(L₁₀, 1)`) до целевого
   `|Lc(candidate, шаг 2)| = 68` (шаг 11) и `= 90` (шаг 12), кандидат сериализуется в css
   и прогоняется через `contrastAPCA` из P2.1. APCA монотонен по luminance при
   фиксированном фоне — поиск сходится. Если целевой Lc недостижим (упёрлись в L→0/1) —
   берём крайнее значение; инвариант-минимумы (см. тесты) при этом всё равно обязаны
   выполняться для тестового набора seeds.
5. **Gamut-маппинг** каждого шага: `toGamut('rgb', 'oklch')` (или `'p3'` при opts.gamut) —
   НЕ `clampChroma` (пересушивает — R-12 §2). hex — из sRGB-маппинга через `formatHex`.
6. **Сериализация**: `oklch(${L} ${C} ${H})`, L/C — 4 знака, H — 2 знака (детерминизм);
   ахромат — `oklch(L 0 0)`.

Пример вход→выход (структурно; точные числа зависят от констант):
`generateScale('oklch(0.55 0.15 155)')` → 12 шагов; шаг 1 ≈ `oklch(0.993 0.003 155)`
(почти белый с намёком на hue), шаг 9 = `oklch(0.55 0.15 155)` (seed), шаг 12 ≈
`oklch(0.19 0.05 155)` — |Lc| против шага 2 ≥ 75.
