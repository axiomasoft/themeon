### P7.1 — Registry пресетов тем (shadcn-style `registry-item.json`)

**Status:** ⬜ Not started
**Intent:** Дать новым потребителям пакета готовые, устанавливаемые копированием пресеты тем
(набор `*.theme.ts` + сопутствующих файлов) через CLI-подкоманду, по аналогии с
`shadcn add` / `registry-item.json`.
**Why:** Снижает трение первого запуска для потребителей за пределами dterema/vintera/Flex*.
Пока нет ни одного такого стороннего потребителя — ценность не подтверждена использованием,
поэтому item задизайнен только на уровне триггера и принципа, не реализации.
**Scope Included:** (после триггера) CLI-подкоманда `themeon add <preset>` в существующем
`themeon`-бинарнике; JSON-манифест пресета (name/type/files/dependencies — форма проверяется
по актуальному shadcn-формату на момент триггера, RAG обязателен); минимум 1 пресет, собранный
из факта реального стороннего консьюмера (не выдуманный «для примера»).
**Scope Excluded:** Сегодня — любая реализация кода. После триггера — хостинг/сервер registry
(статический JSON в репозитории/CDN — решается на месте, не проектируется заранее); установка
пресета как npm-зависимости (нужна копия для кастомизации потребителем, не пакет).
**Inputs:** —
**Files:** — (не спроектировано; при триггере — новый модуль в `packages/cli/src/`)
**Required Reads:** `00_MASTER_PLAN.md` §5 D11, §6.5–§6.6, §7 (риск overengineering) ·
`packages/cli/src/cli.ts` + `packages/cli/src/templates.ts` (существующий citty-каркас
CLI, P-D28 — новая подкоманда обязана лечь в него, не в отдельный бинарник) ·
`plans/2026.07.12-BASE/phases/P4.md` P4.6 (паттерн e2e API-freeze фикстуры для CLI).
**Implementation Rules:** Триггер item'а — появление ≥1 реального стороннего потребителя

### P7.5 — Vue-обёртки примитивов (`<ToStack>` и т.п.)

**Status:** ⬜ Not started
**Intent:** Тонкие Vue SFC-обёртки над CSS-классами composition-примитивов `@themeon/css`
(`<ToStack>`, `<ToCluster>` и т.п.) — синтаксический сахар поверх уже существующих классов
(`.stack`/`.cluster`/…, `packages/css`, фаза P2).
**Why:** `00_MASTER_PLAN.md` §6.5 — **явная рекомендация НЕ делать это в v1**: пакет
позиционируется как «утилиты, не UI-kit»; Vue-компоненты превратили бы ThemeOn в
компонентную библиотеку, конкурирующую с Naive/Vuetify/PrimeVue вместо их темизации.
Item существует как backlog-заготовка на случай сильного сигнала боли от реального
потребителя, а не как одобренное направление по умолчанию.
**Scope Included:** (после триггера, и только если триггер — весомый) тонкие SFC-обёртки,
единственная функция которых — навесить нужный класс/custom-property-параметры на элемент;
без собственной логики/состояния.
**Scope Excluded:** Сегодня — любая реализация. По умолчанию — НЕ делать (§6.5); триггер
обязан включать явное обоснование, почему одних CSS-классов (уже покрывают Blade/plain HTML/
любой фреймворк) недостаточно именно для этого потребителя.
**Inputs:** —
**Files:** —

`packages/css/src` (composition-классы, фаза P2, `phases/P2.md`) — обёртки лишь навешивают
существующие классы, не изобретают новый CSS-контракт.
