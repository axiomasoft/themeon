# P9 — Документация v0.1: VitePress-сайт (структура, гайдлайны, quick-start)

## Phase Context

**Что.** Публичный документационный сайт ThemeOn на VitePress: index-лендинг (hero + сравнение),
секция Introduction (why/install/quick-start/changelog), Basic Usage (по странице на каждый из 9
пакетов), Best Practices (✅/❌-гайдлайны) и Recipes (миграция `docs/laravel.md` + доп. рецепт),
деплой на GitHub Pages. Референс-паттерн — `~/projects/packages/azguard/docs/` (тот же владелец
`axioma-studio`, тот же движок, работающий CI) — **не копия**: несколько мест сознательно улучшены
(актуальные версии GH Actions, pnpm вместо npm/catalog-пин, явный `ignoreDeadLinks`), см.
Implementation Rules P9.1.

**Почему.** Проект приближается к стадии реальных сайтов-потребителей (P5 пилоты закрыты, P7
backlog ждёт триггеров) — пора дать внешнему читателю единую точку входа вместо разрозненных
README пакетов. Версия сознательно **0.1** — структура/навигация почти наверняка изменятся, когда
начнётся разработка конкретных сайтов на ThemeOn (owner, 2026-07-15, см. P-D74) — это НЕ гейт на
полноту, это явное разрешение на будущий передел.

**Scope Included:** VitePress-скелет (nav/sidebar, GH Pages CI); Introduction (why/install/
quick-start/changelog-заглушка); Basic Usage — 9 тонких страниц (по одной на пакет, ссылка на
README пакета за деталями, не дублирование); Best Practices — 2 гайдлайна, оба из РЕАЛЬНОГО канона
пакетов (fail-loud, `@theme reference`); Recipes — миграция `docs/laravel.md` + 1 новый рецепт
(anti-FOUC); финальная сборка (лендинг, аудит мёртвых ссылок, git-тег `docs-v0.1.0`, ссылка из
корневого `README.md`).

**Scope Excluded:** i18n/RU (P-D75, отдельная фаза после стабилизации структуры); кастомная
VitePress-тема (default theme, v0.1); дублирование полного API каждого пакета на сайте (README
пакета остаётся SSOT деталей, сайт — тонкая точка входа); PHP/Blade-документация сверх уже
существующего `docs/laravel.md` (P6.4/P-D72 её не заводили); версионирование пакетов через
Changesets (не трогается — git-тег `docs-v0.1.0` независим, см. P-D77).

**Inputs (сквозные для фазы):** `~/projects/packages/azguard/docs/.vitepress/config.ts` +
`.github/workflows/docs.yml` (референс-паттерн); `README.md` (таблица пакетов); `packages/*/
README.md` (источник ВСЕХ code-примеров — ничего не изобретается заново, см. Code Guidance P9.2/
P9.3); `docs/laravel.md` (мигрируется в P9.4); `plan.md` §1 Context (позиционирование/ниша,
research-верифицировано `20_research/R-01..R-07`).

**Инвариант фазы (все items):** **ни один пример кода на сайте не придуман с нуля** — источник
(файл:строка существующего README/src/теста) указывается в Completion Notes item'а. Это
доковый аналог P8-класса дефекта «зелёный тест на моке границы»: придуманный пример, который не
компилируется/не соответствует реальному API, обманывает читателя дороже отсутствующей страницы.

**Инвариант ссылок фазы (D-P78, все items):** ссылки со страниц сайта на README пакетов —
ВСЕГДА полный GitHub-URL (`https://github.com/axioma-studio/themeon/blob/main/packages/<pkg>/
README.md[#anchor]`, либо `.../tree/main/packages/<pkg>#readme` для anchorless-ссылки на пакет),
НИКОГДА относительный путь наружу `docs/` (`../packages/*/README.md`). Причина: VitePress
резолвит markdown-ссылки по дереву страниц сайта — файл вне `docs/`-корня страницей сайта не
является, поэтому `ignoreDeadLinks: false` (сторож целостности, P9.5) справедливо его отвергает,
и в собранном сайте такая ссылка всё равно не кликабельна (ограничение движка, не опечатка).
Внешние `http(s)://`-ссылки dead-link-чекер VitePress НЕ проверяет — поэтому GitHub-URL проходит
сборку. Конвенция уже действовала в P9.3 (Impl Rule 2); D-P78 поднимает её до инварианта фазы и
чинит 3 нарушивших её ссылки в `docs/laravel.md` (P9.1 Impl Rule 5). RAG:— (repo-grounded:
воспроизведённый build P9.1 — внешний GitHub-URL на строке 82 `laravel.md` прошёл чекер, только
относительные `../packages/*` помечены dead).
