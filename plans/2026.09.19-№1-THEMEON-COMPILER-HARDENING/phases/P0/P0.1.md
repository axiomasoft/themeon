### P0.1 — DTCG 2025.10 support and loss contract

**Intent:** Establish a versioned, evidence-backed DTCG support matrix and make every currently
observable lossy/unsupported path explicit without redesigning the whole compiler.

**Why:** `RAG:—` `packages/core/src/dtcg/**` implements import/export and tests, but there is no
normative feature matrix or declared loss policy. D2 requires explicit preservation/rejection
before P1 changes the internal model; external 2025.10 semantics in the audit remain `[UNVERIFIED]`.

**Scope Included:** Official-spec evidence capture; `docs/standards/dtcg-2025.10.md` matrix for
`$value`, `$type`, group inheritance, `$description`, `$deprecated`, `$extends`, `$extensions`,
aliases, composite values, invalid token/group mix and unknown future types; fixtures documenting
current import/export/validation behavior; stable diagnostics for observed loss or rejection where
the current API can express them without IR redesign; a clearly versioned gap list owned by P1/P2.

**Scope Excluded:** Canonical IR and broad metadata carriage; plugin hooks; physical `@themeon/dtcg`
package; claiming full DTCG compliance; changing TS DSL into JSON authoring; unrelated resolver or
CSS behavior.

**Inputs:** `decisions/D2-dtcg-loss-policy.md`; `findings/audit-verdicts.md`;
`inputs/sources.md`; `audits/2026-09-19-audit.md`; `packages/core/src/dtcg/types.ts`;
`packages/core/src/dtcg/from-dtcg.ts`; `packages/core/src/dtcg/to-dtcg.ts`

**Implementation Rules:** Matrix claims are feature-by-feature and distinguish Import, Preserve,
Validate, Export and Lossless. An unsupported feature is classified as reject-with-diagnostic,
opaque-preserve, or explicit-lossy-option—never silently dropped. Repository observations use
`RAG:—`; external semantics receive `RAG:✅` only with captured primary URL/date. Preserve current
root API compatibility; if a correct loss contract requires new IR fields, record the gap for P1
instead of adding a parallel ad-hoc model here.

**Code Guidance:** Start from behavior characterization: add one fixture/test per matrix row before
changing converters. Use stable diagnostic codes, not message parsing. Compare round trips
semantically (normalized document/value/metadata), not by object insertion order. Keep fixtures
small and name their expected preservation/loss behavior.

**Validation:** `pnpm --filter @themeon/core test`; `pnpm --filter @themeon/core typecheck`;
`pnpm --filter @themeon/core build`; `pnpm check:pack`; a deterministic check proves every matrix
row names at least one fixture/test or an explicit P1 gap; no matrix cell claims “Lossless” when its
fixture drops data.

**Deliverables:** Versioned DTCG matrix with primary-source provenance; current-behavior fixtures;
stable loss/unsupported diagnostics that fit the current model; explicit P1/P2 gap list; GREEN core
package and packed-surface checks.
