# P0 — Correctness, security and release foundation

## Phase Context

P0 closes the audit findings that can invalidate every later compiler claim: undocumented DTCG
loss, APCA-only accessibility semantics, unbounded tenant patches, release trust gaps, publication
status drift and absent risk-focused coverage gates. It changes only current public capabilities
and their evidence; it does not introduce canonical IR or plugin architecture.

`RAG:—` current code already rejects prototype path segments in `define.ts` and exposes typed error
codes, so security and diagnostics work extends those seams instead of replacing them. External
standards assertions remain `[UNVERIFIED]` until P0.1/P0.2 capture official primary-source evidence.

> **Контракт фазы (contract-first).** Потребляет: current public behavior, audit verdicts and
> official standards/release evidence. Производит: explicit DTCG support/loss matrix, normative
> contrast policy, tenant threat-model enforcement, trusted-release workflow, synchronized package
> truth and measured critical coverage gates. Границы: no compiler IR, no package split, no release
> publication/tag, no trigger-gated ecosystem package.

> **Phase Assurance | v1.**
> Impact: security-external
> Integration Seams: dtcg-io · contrast-cli · tenant-patch · release-trust · package-coverage
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: Each public/security item has focused adversarial or contract validation and `full`
> review where required; external trust activation is isolated behind an owner gate.

## Scope Included

DTCG 2025.10 compliance inventory and loss behavior; WCAG 2.2 contrast results with APCA advisory;
tenant patch resource/path/size/depth/schema defenses; reusable full verification and OIDC-ready
release workflow; publication and manifest truth; critical-module coverage thresholds based on a
measured baseline.

## Scope Excluded

Canonical IR/compiler/plugin implementation (P1); property/mutation/consumer/performance programme
(P2); CLI explain/diff and new tooling packages (P3); actual npm publication or tag; framework
adapters and consumer-triggered ecosystem work.

and may reuse P0.5 root-manifest context. P0.4 in-plan close is repository+CI plumbing (D10, `🟠`);
external trusted-publisher configuration is residual outside this plan and does not block later
