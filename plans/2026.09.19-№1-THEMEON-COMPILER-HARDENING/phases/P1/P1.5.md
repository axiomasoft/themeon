### P1.5 — Staged compiler, fingerprint and scoped extensions

**Intent:** Compose normalize→validate→resolve→transform→validate-output→emit as explicit immutable stages with deterministic fingerprints and instance-scoped extensions.

**Why:** One pipeline is required to stop adapters from re-resolving or mutating themes and to make caching safe.

**Scope Included:** Compiler/context/result contracts; pure built-in transforms/formats; build fingerprint; declared extension capabilities/order/cache contribution; sync-first execution.

**Scope Excluded:** Global registry; build-time network; arbitrary plugin side effects; new package.

**Inputs:** `phases/P1/P1.2.state.md`; `phases/P1/P1.3.state.md`; `phases/P1/P1.4.md`; `phases/P1/P1.4.state.md`; `decisions/D1-compatibility-first-compiler.md`

**Files:** `packages/core/src/{pipeline,transforms,formats}/**`; compatibility serializers; compiler integration tests.

**Required Reads:** `plan.md`; `phases/P1/P1.md`; `phases/P1/P1.2.md`; `phases/P1/P1.3.md`; `phases/P1/P1.4.md`; `packages/core/src/serialize.ts`; `packages/core/src/apply.ts`; `packages/core/src/naming.ts`; `packages/vite/src/index.ts`; `packages/tailwind/src/index.ts`; `packages/naive/src/index.ts`; `decisions/D1-compatibility-first-compiler.md`

**Implementation Rules:** Stage inputs/outputs are immutable; declared extension ordering is deterministic; fingerprint includes every behavior-affecting input and version; formatters cannot resolve.

**Code Guidance:** Keep orchestration thin; provide explicit stage hooks rather than generic middleware; test extension collisions and missing cache contribution.

**Validation:** Compiler parity and determinism fixtures; extension isolation; fingerprint sensitivity/stability; affected package tests; root build/typecheck/lint/test/check:pack.

**Deliverables:** Staged compiler, built-ins, scoped extension registry, fingerprint contract and compatibility adapters.
