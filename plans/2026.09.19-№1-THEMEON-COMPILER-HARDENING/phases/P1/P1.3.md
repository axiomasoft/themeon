### P1.3 — Reference graph and deterministic resolution

**Intent:** Build and validate a reference graph, then resolve it deterministically with explicit cycle and dependency-policy diagnostics.

**Why:** Recursive value resolution cannot provide dependable topology, provenance or cycle evidence for later compilation and explanation.

**Scope Included:** Graph construction; alias/composite edges; missing/cycle detection; stable topological order; dependency policy; resolved immutable IR.

**Scope Excluded:** CSS formatting; CLI graph UI; arbitrary plugin I/O.

**Inputs:** `phases/P1/P1.2.md`; `phases/P1/P1.2.state.md`; `phases/P0/P0.1.state.md`; `phases/P0/P0.3.state.md`; `decisions/D1-compatibility-first-compiler.md`

**Files:** `packages/core/src/graph/**`; `packages/core/src/resolve.ts`; graph/resolution fixtures and compatibility tests.

**Required Reads:** `plan.md`; `phases/P1/P1.md`; `phases/P1/P1.1.md`; `phases/P1/P1.1.state.md`; `phases/P1/P1.2.md`; `phases/P1/P1.2.state.md`; `phases/P0/P0.3.md`; `packages/core/src/resolve.ts`; `packages/core/src/resolve.test.ts`; `packages/core/src/errors.ts`; `packages/core/src/dtcg/from-dtcg.test.ts`

**Implementation Rules:** No recursion without bounded/cycle-aware state; order derives from canonical identity, never insertion order; errors carry stable code/path/provenance.

**Code Guidance:** Separate graph build, validation and evaluation; retain an adapter for legacy `resolve*`; test multi-node and composite cycles.

**Validation:** Graph/resolver suite; permutation tests produce identical output; adversarial depth/cycle tests terminate; legacy resolver parity and root verification.

**Deliverables:** Reference graph API, deterministic resolver, dependency-policy checks, failure taxonomy for P1.4 and adversarial fixtures.
