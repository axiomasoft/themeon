### P1.4 — Structured diagnostic contract and adapters

**Intent:** Establish stable structured diagnostics shared by core and build-tool consumers without coupling core to presentation.

**Why:** Existing errors cannot reliably power CI annotations, explainability or cross-package parity when consumers parse messages.

**Scope Included:** Diagnostic schema/codes/severity/location/path/provenance; aggregation; pretty/plain/json adapter interfaces; migrations in CLI/Vite/Nuxt.

**Scope Excluded:** Final CLI commands and GitHub formatter (P3); telemetry service; message localization.

**Inputs:** `phases/P0/P0.1.state.md`; `phases/P0/P0.2.state.md`; `phases/P0/P0.3.state.md`; `phases/P1/P1.1.state.md`; `phases/P1/P1.2.state.md`; `phases/P1/P1.3.md`; `phases/P1/P1.3.state.md`

**Files:** `packages/core/src/diagnostics/**`; `packages/core/src/errors.ts`; affected CLI/Vite/Nuxt adapters and tests.

**Required Reads:** `plan.md`; `phases/P1/P1.md`; `phases/P1/P1.2.md`; `phases/P1/P1.3.md`; `packages/core/src/errors.ts`; `packages/core/src/errors.test.ts`; `packages/cli/src/check.test.ts`; `packages/vite/src/index.test.ts`

**Implementation Rules:** Machines consume codes/fields, not text; additive code evolution; redact unsafe tenant values; formatter never changes severity or ordering.

**Code Guidance:** Keep schema serializable and framework-free; map legacy errors at a single boundary; snapshot structured objects separately from rendered text.

**Validation:** Schema/type tests; redaction/adversarial fixtures; consumer parity tests; stable JSON/order; core zero-dependency check.

**Deliverables:** Diagnostic schema/catalog, adapters, legacy mapping and consumer contract tests.
