### P2.1 — Property suites and deterministic generators

**Intent:** Prove algebraic and round-trip properties of the frozen resolver, IR, DTCG, patch and serialization contracts.

**Why:** Example tests miss ordering, graph and composition failures across the expanded input space.

**Scope Included:** Ecosystem-reuse check; seeded generators/shrinkers; determinism, idempotence, round-trip and patch-composition properties; replay corpus.

**Scope Excluded:** New product semantics; unseeded flaky fuzzing; mutation or browser testing.

**Inputs:** `phases/P1/P1.2.state.md`; `phases/P1/P1.3.state.md`; `phases/P1/P1.5.state.md`; `phases/P1/P1.6.state.md`; `phases/P0/P0.1.state.md`; `phases/P0/P0.3.state.md`; `phases/P0/P0.6.state.md`

**Files:** Focused `packages/core` property tests; `tests/fixtures/generated/**`; selected test config and CI lane.

**Required Reads:** `plan.md`; `phases/P2/P2.md`; `phases/P1/P1.closed.md`; `phases/P0/P0.md`; `vitest.config.ts`; `package.json`; `findings/audit-verdicts.md`

**Implementation Rules:** Seeds and size budgets are reproducible; every failure persists a minimal replay; generators only create invalid states when testing validation.

**Code Guidance:** Start with hand-written generators; adopt a library only when reuse beats maintenance; separate law definitions from generators.

**Validation:** Two runs with fixed seeds match; forced-bug self-test demonstrates failure/shrinking; PR runtime stays within recorded budget; root tests green.

**Deliverables:** Tool decision, generators, named properties, replay corpus and CI command.
