# @themeon/tailwind

Tailwind v4 bridge: `@theme reference` block so `[data-theme]` swaps reach generated
utilities.

## Main exports

| Export | What it does |
|:--|:--|
| `tailwindBridge` | Generates a `@theme reference { … }` block (literal values) from a resolved ThemeOn theme, so Tailwind generates utilities under the same class names. |
| `TailwindBridgeOptions` (type) | `include`/`namespaces`/`banner`. |
| `TAILWIND_NAMESPACES` | The var namespaces Tailwind v4 recognises for utility generation (`color`, `spacing`, `radius`, `shadow`, …). |
| `TAILWIND_LAYER_ORDER` / `tailwindLayerPreamble` | The `@layer` order statement that fixes precedence between Tailwind's own layers and `themeon.*` (see `themeon build --tailwind-layers`). |

## Example

```ts
import { resolveTheme } from '@themeon/core'
import { tailwindBridge } from '@themeon/tailwind'
import { theme } from './theme.config'

const resolved = resolveTheme(theme)
const bridgeCss = tailwindBridge(resolved)
// write bridgeCss to ./theme-bridge.css (build step — see `themeon build --tailwind`)
```

```css
/* app.css */
@import "tailwindcss";
@import "./theme-bridge.css"; /* generated by tailwindBridge — @theme reference block */
@import "./tokens.css";        /* @themeon/core serializeThemeCss output — the values */
```

`@theme reference` never emits the referenced variables into `:root, :host`, so import order
between `bridge.css`, `tokens.css` and `tailwindcss` doesn't matter.

Full API & options → [`packages/tailwind/README.md` on GitHub](https://github.com/axioma-studio/themeon/tree/main/packages/tailwind#readme).
