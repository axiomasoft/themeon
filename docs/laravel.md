# Laravel + Vite

Laravel projects consume ThemeOn exactly like any other Vite project — `ThemeOn ships no
framework glue for Laravel` (`@themeon/vite` README), Composer/Blade packages are out of scope
(deferred to FlexCMS). There are **three distinct connection channels**. Pick the one that
matches your setup — they are not interchangeable, and mixing their recipes is the single most
common Laravel-integration mistake.

| Channel | What | How it's wired | CSS `@import` works? |
|:--|:--|:--|:--|
| **A. Static default theme** | `@themeon/css/tokens.css` — a real, pre-built file shipped by the package | `@import "@themeon/css/tokens.css"` in `resources/css/app.css` | **Yes** |
| **B. Custom theme** | `virtual:themeon.css` — a virtual module generated by the `@themeon/vite` plugin from your TS token file | JS/TS import only: `import 'virtual:themeon.css'` in a JS entry | **No, never** |
| **C. Pure Blade, no JS entry** | Same virtual module as B | `@themeon/vite`'s `cssImport` option | Yes (writes a real file, then aliases the virtual id to it) |

## A. Static default theme — `@import` in `app.css`

Use this when you just want the package's shipped default theme (light + `dark` via
`[data-theme]`) with no per-project token customization. No `@themeon/vite` plugin required —
`@themeon/css` alone is enough.

```js
// vite.config.js
import laravel from 'laravel-vite-plugin'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [laravel({ input: ['resources/css/app.css', 'resources/js/app.js'] })],
})
```

```css
/* resources/css/app.css */
@import "@themeon/css/tokens.css";
@import "@themeon/css/index.css";
```

This works because Vite's CSS pipeline resolves `@import` through `postcss-import`, which
follows Node package resolution and package `exports` — `@themeon/css` opens the `./tokens.css`
subpath (`packages/css/package.json` → `exports["./tokens.css"]`), so the bare specifier
resolves to a real on-disk file in both dev and production builds. `laravel-vite-plugin` does
not change CSS resolution at all — it only points Vite at your entries and emits `@vite(...)`
tags for the compiled assets.

**This is verified by a real `vite build`, not assumed:**
`tests/integration/src/browser/laravel-css-import.test.ts` builds a fixture whose `app.css`
contains exactly the snippet above and asserts the compiled CSS contains `--color-bg-page` /
`--radius-md`. The resolution depends on the package's `exports` map staying open on that
subpath — if it were ever closed, this recipe would silently stop working even though the file
still physically exists on disk (the same class of defect a prior audit found hiding behind a
mocked resolver, `findings/P8-*.md` Blocker #1) — the test guards against exactly that.

## B. Custom theme — `virtual:themeon.css` (JS import only)

Use this to compile **your own** `theme.config.ts` tokens instead of the shipped default. This
is the `@themeon/vite` plugin's canonical channel — full setup, HMR, and the anti-FOUC script
are documented in [`packages/vite/README.md`](../packages/vite/README.md#laravel--vite).

```js
// vite.config.js
import laravel from 'laravel-vite-plugin'
import { defineConfig } from 'vite'
import { themeon } from '@themeon/vite'
import { theme } from './resources/theme.config'

export default defineConfig({
  plugins: [
    laravel({ input: ['resources/css/app.css', 'resources/js/app.js'] }),
    themeon({ theme, tokensFiles: ['./resources/theme.config.ts'], injectFouc: true }),
  ],
})
```

```js
// resources/js/app.js
import 'virtual:themeon.css'
```

**Do not** add `@import 'virtual:themeon.css'` to `resources/css/app.css` — it never resolves.
Vite's CSS pipeline resolves `@import` through `postcss-import`'s own filesystem-only resolver;
plugin `resolveId`/`load` hooks (which is how `@themeon/vite` serves the virtual module) are
never consulted for `@import` targets in CSS files. This is not a bug specific to this plugin —
[UnoCSS's `virtual:uno.css` has the identical restriction](https://github.com/unocss/unocss/issues/3853).
See "Why not CSS `@import`?" in the vite plugin README for the full explanation, and the
antipode test below for the proof that it fails, not silently no-ops.

**Guarded by the same integration test as channel A** (sibling case in
`laravel-css-import.test.ts`): a fixture whose `app.css` contains `@import "virtual:themeon.css"`
with no `@themeon/vite` plugin in the graph is asserted to make `vite build` **throw** — proving
channel A and channel B are not interchangeable, not just documenting it.

## C. Pure Blade, no JS entry

If your Laravel view has no JS/TS entry point at all (a CSS-only Blade layout), enable the
plugin's `cssImport` option — it writes the compiled theme CSS to a real file on disk and
aliases the virtual id to it, so the `@import 'virtual:themeon.css'` syntax works after all
(because it now points at an ordinary file, not a virtual module). Full recipe:
[`packages/vite/README.md` — "CSS-only projects"](../packages/vite/README.md#css-only-projects-no-js-entry).

## Anti-FOUC in a Blade layout

Vite's `transformIndexHtml` hook (which `@themeon/vite`'s `injectFouc` option uses) never runs
for classic Laravel setups — Laravel serves Blade templates, not `index.html`. Inline the same
anti-FOUC script yourself, as early as possible in the `<head>` of your Blade layout, using the
pure subpath `@themeon/vue/anti-fouc` (zero Vue imports — safe to use even in a project with no
Vue in its dependency graph):

```php
{{-- resources/views/layouts/app.blade.php --}}
<head>
    <script>{!! $themeInitScript !!}</script>
    @vite(['resources/css/app.css', 'resources/js/app.js'])
</head>
```

```ts
// wherever you render the layout (a service provider, a view composer, …)
import { themeInitScript } from '@themeon/vue/anti-fouc'

const script = themeInitScript({ storageKey: 'themeon-theme', attribute: 'data-theme' })
// pass `script` to the Blade view as `$themeInitScript`
```

Pass the view the same `storageKey`/`attribute` (and `themes`/`default`, if customized) you use
on the frontend side (`useTheme()` from `@themeon/vue`, if you use it) — the script and the
runtime composable are two channels of one piece of state, not two independent configs.

## What ThemeOn does not ship for Laravel

No Composer package, no Blade component, no PHP helper — `ThemeOn ships no framework glue for
Laravel` (deferred to FlexCMS, see the plan's Not-a-goal list for this phase). The three
channels above are the complete Laravel-facing surface: two Vite-plugin channels already
documented in [`packages/vite/README.md`](../packages/vite/README.md), plus this page's channel
A for the common case of "just use the shipped default theme".
