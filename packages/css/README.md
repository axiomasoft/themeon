# @themeon/css

CSS foundation for ThemeOn: `@layer` cascade, reset, base typography, layout composition
primitives, site blueprints and component skeletons — all on CSS custom properties. Ships a
generated default theme (`tokens.css`) so the foundation works out of the box in plain HTML,
with zero runtime JavaScript dependencies.

## Quickstart

```html
<link rel="stylesheet" href="node_modules/@themeon/css/dist/tokens.css" />
<link rel="stylesheet" href="node_modules/@themeon/css/dist/index.css" />
```

or, with a bundler resolving package exports:

```css
@import "@themeon/css/tokens.css";
@import "@themeon/css/index.css";
```

`tokens.css` must be imported **before** `index.css` (or any other entry) — it declares the
`sys`-layer custom properties every other layer falls back to. Every `var()` in the package's
own CSS also carries a literal fallback (P-D19), so the package still renders sensibly even
without `tokens.css` — but colors/spacing/radii will be generic neutrals, not the shipped
palette.

## Entry files

| Entry (`exports` subpath) | Layer(s) | Content |
|:--|:--|:--|
| `./tokens.css` | `themeon.tokens` | Generated default theme (light base + `dark` theme) — `@themeon/core` + `@themeon/colors` dogfood, byte-for-byte `serializeThemeCss` output, **not** minified (P-D22) |
| `./layers.css` | — | `@layer` order declaration only (first statement of every other entry) |
| `./reset.css` | `themeon.reset` | Minimal intentional reset (box-sizing, margin, focus-visible outline, …) |
| `./base.css` | `themeon.base` | Tag typography (`body`/`h1..h4`/`p`/`a`/`code,pre,kbd`/`small`/`hr`) on contract variables |
| `./composition.css` | `themeon.composition` | 8 layout primitives: `.container`/`.stack`/`.cluster`/`.with-sidebar`/`.center`/`.cover`/`.switcher`/`.grid` |
| `./blueprints.css` | `themeon.blueprints` | Site-zone recipes: `.page-shell`/`.site-header`+`.site-nav`/`.hero`/`.section`/`.site-footer` (see [Blueprints](#blueprints) below) |
| `./components.css` | `themeon.components` | `.btn`/`.badge`/`.card`/gradient utilities |
| `./utilities.css` | `themeon.utilities` | 6 intentional utilities (`.visually-hidden`, `.text-center/-start/-end`, `.text-muted`, `.text-balance`) |
| `./index.css` | all of the above except `tokens` | Convenience aggregate — everything but the theme, so you can bring your own `tokens.css` |
| `.` (JS) | — | `CSS_CONTRACT` / `THEMEON_LAYERS` — machine-readable variable contract, input for `themeon check` (P4) |

`@layer` order (declared once, first statement of every entry — R-12 §5):

```
themeon.tokens, themeon.reset, themeon.base, themeon.composition,
themeon.blueprints, themeon.components, themeon.utilities
```

Any unlayered rule in your own stylesheet outranks all of them regardless of source order or
specificity (native cascade-layer semantics) — overriding the package never requires
`!important` (D8).

## CSS variable contract

The variables `@themeon/css`'s own CSS consumes (`sys`-layer, all with literal fallbacks —
P-D19). This is a subset of what the default theme actually ships in `tokens.css` (which also
defines `--color-border-strong`, `--text-lg`, `--spacing-2xs`/`--spacing-3xl`,
`--duration-base` and the `--breakpoint-*` scale for your own use).

| Group | Variables | Fallback policy |
|:--|:--|:--|
| font | `--font-sans`, `--font-mono` | `system-ui, sans-serif` / `ui-monospace, monospace` |
| color | `--color-bg-page`, `--color-bg-subtle`, `--color-bg-elevated`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-action-primary`, `--color-action-primary-hover`, `--color-on-primary`, `--color-focus-ring`, `--color-link`, `--color-link-hover` | neutral oklch literals (light theme) |
| text | `--text-{base,sm,xl,2xl,3xl,4xl}` + `--text-*--line-height` companions | rem scale |
| spacing | `--spacing-{xs,sm,md,lg,xl,2xl}` | 0.5/0.75/1/1.5/2/3 rem |
| radius | `--radius-{md,lg,full}` | 0.5/0.75rem/999px |
| shadow | `--shadow-{sm,lg}` | light `rgb(0 0 0 / a)` |
| motion | `--ease-standard`, `--duration-fast` | `ease`, 150ms |
| gradient | `--gradient-brand` | `linear-gradient` on `--color-action-primary` |

The exact, always-current list lives in `CSS_CONTRACT` (`src/contract.ts`, JS entry `.`) — a
test (`test/contract.test.ts`) keeps it in sync with the real CSS and with `dist/tokens.css`.

## Bringing your own tokens

`tokens.css` is generated by this package from a `@themeon/core` `defineTheme` call — you are
not required to use it. Author your own theme with `@themeon/core` directly and serve its
`serializeThemeCss` output instead, as long as it defines the variable names from the
contract table above (and their `dark`-theme counterparts, if you use `[data-theme="dark"]`):

```ts
import { defineTheme, resolveTheme, serializeThemeCss } from '@themeon/core'

const theme = defineTheme({
  base: {
    color: { bg: { page: '#fff' }, text: '#111', /* … */ },
    font: { sans: 'Inter, sans-serif', mono: 'ui-monospace, monospace' },
    // … the rest of the contract table
  },
  themes: { dark: { color: { bg: { page: '#111' }, text: '#eee' } } },
})

const css = serializeThemeCss(resolveTheme(theme))
```

Then import your generated stylesheet instead of `@themeon/css/tokens.css`, before
`@themeon/css/index.css`.

## Co-existing with Tailwind v4

Tailwind v4 also uses native `@layer` (`theme, base, components, utilities` by default). Both
systems' layer orders can coexist in the same cascade as long as ThemeOn's layer-order
statement is declared **before** Tailwind's `@import "tailwindcss"` — the browser keeps the
order of the *first* mention of each layer name, and mixing unrelated layer names (`themeon.*`
vs Tailwind's unprefixed names) does not create a specificity conflict either way:

```css
@import "@themeon/css/layers.css"; /* declares the themeon.* order first */
@import "tailwindcss";
@import "@themeon/css/tokens.css";
@import "@themeon/css/index.css";
```

To scope one of this package's stylesheets *inside* a layer of your own naming (e.g. to keep
it below a `vendor` layer in your own order), wrap the import:

```css
@import "@themeon/css/reset.css" layer(vendor);
```

This is the same pattern used by MUI's CSS Layers integration — `@import … layer(name)`
re-parents everything the imported file declares into your named layer, regardless of the
layer names it declares internally.

## Blueprints

Site-blueprint classes (`@layer themeon.blueprints`) are CSS-only recipes for common page
zones — `@themeon/css` never ships markup or JavaScript, only the styling. Copy the HTML
snippets below into your templates/components.

### `.page-shell`

Page wrapper: a full-height flex column that pins the footer to the bottom, and declares
the named `page` container that `.site-header`'s burger threshold below queries via
`@container page (...)`.

```html
<body class="page-shell">
  <header class="site-header">…</header>
  <main>…</main>
  <footer class="site-footer">…</footer>
</body>
```

| Parameter | Default |
|:--|:--|
| — | (no local parameters; `container: page / inline-size` is fixed) |

### `.site-header` + `.site-nav` (burger menu)

Horizontal navigation on wide viewports; below a **48rem** inline-size threshold the nav
collapses into a burger button that opens a CSS-only popover panel. The panel uses the
native **Popover API** (`popover` / `popovertarget`): the browser provides light-dismiss,
<kbd>Esc</kbd>-to-close and top-layer stacking for free — no JavaScript required.

```html
<header class="site-header">
  <a href="/">Brand</a>
  <nav class="site-nav">
    <a href="/features">Features</a>
    <a href="/pricing">Pricing</a>
  </nav>
  <button class="nav-burger" popovertarget="site-menu" aria-label="Menu">☰</button>
  <nav id="site-menu" class="nav-menu" popover>
    <a href="/features">Features</a>
    <a href="/pricing">Pricing</a>
  </nav>
</header>
```

| Parameter | Default |
|:--|:--|
| `--header-gap` | `var(--spacing-md, 1rem)` |
| `--header-pad-block` | `var(--spacing-sm, 0.75rem)` |
| `--header-pad-inline` | `var(--spacing-md, 1rem)` |
| `--nav-gap` | `var(--spacing-md, 1rem)` |

**Overriding the 48rem threshold.** The breakpoint is a fixed value inside
`@container page (inline-size < 48rem) { … }` — `var()` is not allowed inside container-query
conditions per spec, so it cannot be parameterized with a custom property. To use a different
threshold, copy the `@container` block into your own (unlayered) stylesheet with your value:
an unlayered rule always wins over a `@layer`-scoped one, regardless of source order or
specificity, so your override applies without touching the package.

**Anchor Positioning degradation.** Pinning the open panel next to the burger button uses
CSS Anchor Positioning (`anchor-name` / `position-anchor`) as a progressive enhancement
behind `@supports (anchor-name: --nav)`. Without support, the menu still opens and is fully
usable — the browser's default Popover placement centers it in the top layer.

### `.hero`

Centered introductory section with a measure-limited content column.

```html
<section class="hero">
  <h1>Ship your design system, not another CSS reset</h1>
  <p>Typed tokens → CSS variables → adapters, in one package.</p>
</section>
```

| Parameter | Default |
|:--|:--|
| `--hero-pad-block` | `clamp(4rem, 12vi, 8rem)` |
| `--hero-max` | `60ch` |

### `.section`

Vertical rhythm for page sections, with a `.section--subtle` modifier for alternating
section backgrounds.

```html
<section class="section">…</section>
<section class="section section--subtle">…</section>
```

| Parameter | Default |
|:--|:--|
| `--section-pad-block` | `clamp(3rem, 8vi, 6rem)` |

### `.site-footer`

Muted-background footer with an auto-fit column grid (`.footer-cols`).

```html
<footer class="site-footer">
  <div class="footer-cols">
    <div>Product</div>
    <div>Company</div>
    <div>Legal</div>
  </div>
</footer>
```

| Parameter | Default |
|:--|:--|
| `--footer-pad-block` | `var(--spacing-2xl, 3rem)` |
| `--footer-pad-inline` | `var(--spacing-md, 1rem)` |
| `--footer-gap` | `var(--spacing-xl, 2rem)` |
